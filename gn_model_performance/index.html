    GN simulation performance investigation — 24 October 2026

    The implemented changes reduce repeated GN calculations and bound candidate-state memory while retaining the existing admission checks. On directed NSFNET with 420 slots, code changes alone made a 16-step RMSA rollout 4.44× faster and reduced action-mask temporary buffers 24.48×. Further ordinary-JAX work removes infeasible/duplicate candidate evaluations and zero-interferer arithmetic. Against the first optimized version, a 1,376-slot 16-environment rollout improves another 2.15×, reaching 619 requests/s with real admitted warmup traffic and full SNR checks.

    These are performance and implementation-equivalence results. The independent formula audit below identifies pre-existing discrepancies that need physical-model validation before making stronger multiband accuracy claims.

    Implemented architecture

    Masking semantics retained by the optimization

    rsa_gn_model inherits the spectrum-only RSA mask and accepts requests based on spectrum availability. GN SNR is evaluated separately for its throughput objective; it does not enforce per-request SNR or fibre-power admission checks. A misleading comment claiming otherwise has been corrected.

    rmsa_gn_model computes a separate footprint and required SNR for every path and modulation format. It tests first-fit and last-fit placements for each pair, not every interior placement. Each tested candidate must satisfy spectrum and power constraints, the new connection's SNR threshold plus admission margin, and existing connections' stored modulation thresholds. The existing-connection check uses the base thresholds without reapplying the admission margin. If several formats pass at the same path/start slot, the mask stores the highest-SE format. The step reads that stored format and uses its SE to determine the allocated width. Modulation correction, when enabled, also uses the hypothetical candidate's format.

    This is implicit format selection. An agent that explicitly chooses modulation needs a joint or conditional mask that retains that dimension. A compact list of physically evaluated (path, format, placement) candidates could expose format choice without expanding to every path/format/slot combination. A conditional policy alone does not remove the cost of checking whether its earlier choices have any physically valid completion.

    Occupied-path SNR accumulation

    Previously, get_lightpath_snr formed SNR arrays for every possible route and every slot, then gathered values for the paths actually referenced by the state. Directed NSFNET with k=5 has 911 route rows, including the dummy row, and 44 links.

    Environment creation now precomputes a padded (paths, maximum_hops) table of constituent link indices. SNR accumulation gathers only the links of each path referenced by the (links, slots) state. Its intermediate work scales with links × slots × maximum_hops, independent of the number of unused route rows. This also avoids zero-times-infinity contamination from off-path zero SNR entries. ROADM and transceiver noise retain their path-level treatment. Empty paths, packed path bits and single-slot shapes have regression coverage.

    Shared baseline and selective link refresh

    RMSA masking evaluates first-fit and last-fit placements for each route/modulation pair: 40 candidates for five routes and four formats. Previously each candidate recomputed link SNR over the whole network.

    Masking now refreshes the current network once, then each candidate recalculates only the links on its route. Unchanged links reuse that shared baseline. Importantly, the baseline is recomputed rather than trusting state.link_snr_array: departures can leave that cache stale. Both generic and fused link-SNR helpers accept selected link indices, retaining their ordering and duplicates.

    Existing lightpaths are still checked across their complete routes. Selective GN refresh does not mean that disruption checks inspect only the new lightpath.

    Bounded candidate batches (first optimization stage)

    Candidate states are constructed inside jax.lax.map, rather than materializing every hypothetical network simultaneously. The measured default is up to 40 candidates per batch for at most 128 slots, and eight for wider spectra. Batching one candidate at a time substantially reduced memory but slowed small workloads; 32- and 40-candidate experiments motivated the small-spectrum policy.

    Invalid candidates remain masked. A batched lax.cond may execute invalid lanes, so this change does not claim that every invalid candidate avoids GN work. The storage bound comes from batching. See the JAX map documentation.

    Measurements

    Runs used Turin's NVIDIA A100 80 GB PCIe GPUs, with JAX preallocation disabled. GPUs 2 and 3 were available; jobs on GPUs 0 and 1 were left alone. Each result separates compilation from synchronized execution, performs three warmups, and reports the median of 7–20 measurements. Rollouts contain 16 actual environment steps. Measurements exclude neural-network training, compilation and host logging.

    Memory columns are XLA compiled temporary-buffer estimates, not total VRAM or process peak memory. Arguments, outputs, constants and allocator/compiler memory are additional. Small timings near the dispatch floor show noise and should not be interpreted as precise microsecond-level comparisons.

    The 420-slot workload gains only about 4% throughput from 64 to 256 environments. The wider workload gains about 6% from 16 to 64. Larger batches fit, but are not automatically useful: there is already parallel work across links, channel pairs and candidate placements within one environment. More environments add independent GN work; they do not make that work reusable.

    An Nsight Systems node-level CUDA graph trace of one warmed-up 64-environment, 420-slot mask recorded 148 kernels with 22.65 ms of summed kernel time in a 22.69 ms kernel window. The union of kernel intervals occupies 99.8% of that window. Host launch gaps are therefore small in this case. The largest fusion, input_scatter_fusion, takes 63.6% of kernel time. Its optimized HLO includes the candidate GN SNR computation, including XPM atan arithmetic, fused into the selected-link scatter; its name does not mean the time is just array scattering.

    This establishes a GPU execution bottleneck, not whether arithmetic throughput, instruction latency, cache traffic or HBM bandwidth dominates that fusion. Nsight Compute counter collection failed with a driver-resource-unavailable error; a DCGM profiling-field read also failed. Neither tool's failed counter collection provides evidence of bandwidth saturation. Dense slot-pair arithmetic (including empty slots) and repeated candidate evaluations remain the strongest algorithmic targets. The kernel summary and CUDA API summary are saved; the full trace and HLO remain on Turin. See NVIDIA's profiling guide for the distinction between timing traces and utilization/roofline counters.

    RSA GN variant

    At 420 slots on JAX 0.12.0.1, RSA GN rollouts measured 6.563 ms before and 6.554 ms after: essentially unchanged. Standalone path-SNR temporaries fell from 3.06 MiB to 0.21 MiB. Its Shannon-throughput calculation measured approximately 0.41 ms on both versions with unchanged temporary storage.

    rsa_gn_model intentionally defers physical-layer refresh/capacity evaluation in places where rmsa_gn_model performs admission checks. These modes should not be treated as equivalent measurements of per-request physical feasibility. The shared path-SNR change benefits both, while the candidate rearchitecture primarily targets RMSA GN masking. The RSA capacity routine remains a possible subsequent optimization.

    Further reductions in wasted work

    These follow-up changes build on 804c53a. Comparisons in this section use that first optimized version as the baseline, with the same JAX 0.12.0.1 runtime and benchmark harness. They must not be multiplied into the earlier 4.44× comparison: the traffic, occupancy, parallelism and runtime differ.

    Compact feasible candidates and reuse physical footprints

    For non-differentiable spectra wider than 128 slots, availability and fibre-power checks run before GN. A fixed-capacity index buffer packs the feasible candidates; a dynamic loop evaluates only the live batches of eight. Identical placements share SNR evidence when their route, start, width and launch power match. The key also includes modulation when modulation correction or Raman amplification is enabled, so format-dependent physics is not shared incorrectly.

    The evidence records endpoint SNR, minimum SNR on newly assigned slots, and whether all old connections pass. Each candidate then applies its own modulation threshold and margin. Equal-width formats therefore retain different admission requirements. Small spectra and differentiable mode keep the previous static traversal. A first attempt added about 6% rollout overhead at 100 slots; keeping the original validity calculation on that path recovered essentially unchanged performance.

    Under an outer environment vmap, the dynamic loop still runs to the largest live candidate count in the batch. Padding in its final batch may execute. This removes whole unused batches; it does not guarantee zero work for every invalid lane.

    Skip zero interfering channels in uniform-span XPM

    The uniform-span, no-modulation-correction fused model now packs interferers with nonzero power and bandwidth, and traverses them in 128-column tiles using ordinary JAX. All output slots remain. The reduction uses the original total power for Raman tilt; repeated-centre occupied slots remain separate contributions. Only exactly zero pair contributions are removed. This is not channel aggregation or a physical approximation, and the existing physical formulas are unchanged.

    The default enables this at 420 slots and above, the measured wide-spectrum range, and retains dense fusion below that threshold and for differentiable environments. Generic/non-uniform and modulation-corrected GN calculations keep their previous physical kernels. Active counts may differ per link; a vmapped JAX loop stops at the largest live count in the mapped batch. Reduction order can change float32 rounding, so equivalence is numerical rather than bitwise for SNR.

    Equivalence tests establish preservation of the implemented model. They do not establish agreement with an independent physical propagation model.

    The independent coefficient audit follows the grouping and channel axes of the cited Semrau implementation, retaining XLRON's beta4 expression. It exposes two pre-existing discrepancies:

    1. _spm and its uniform/fused inlined forms apply the leading coefficient to only the first of the two bracketed contributions. The reference applies it to their sum. The eight-channel diagnostic differs by about 1.06% in SPM efficiency.
    2. The generic _xpm receives one-dimensional channel power/bandwidth inputs from the environment; their .T operations do not create channel-of-interest and interferer axes. The fused implementation uses explicit axes. The heterogeneous eight-channel diagnostic differs by up to 121% in XPM efficiency.

    These percentages concern the diagnostic coefficients, not total SNR error or all operating points. The production formulas were preserved so performance and physics changes can be reviewed independently. Multislot channel-versus-slot power accounting also deserves an independent validation case: the fibre power-budget helper deduplicates channel blocks, while the GN tilt sums the per-slot power array.

    The public DRA module is a NotImplementedError stub pending publication. DRA timing and physical regression checks need the actual implementation. Also, the base model documents a linear Raman-slope approximation with C+L applicability; a wider numerical stress run alone cannot validate S-band or broader multiband accuracy.

    Further architecture opportunities

    These are proposals inferred from the code and measurements, not implemented or benchmarked speedup claims:

    1. Validate and unify the physical kernels first. Add independent SPM/XPM, heterogeneous power, multislot and broad-spectrum references before combining generic/fused execution or changing channel representations.
    2. Aggregate repeated occupied centres with explicit weights. This PR now skips zero interferers in the wide uniform-span path, but every occupied slot still contributes separately. Weighted channel aggregation could reduce pair calculations further. Weights must preserve the intended power/PSD accounting; simply dropping duplicate slots changes the current result.
    3. Cache frequency-dependent pair kernels. The Raman term (a + abar - f * total_power * Cr)^2 is quadratic in total power. On a fixed frequency/bandwidth grid, static pair coefficients could turn repeated transcendental calculations into weighted reductions/matrix products. Variable channel centres, bandwidths and modulation corrections require separate handling.
    4. Extend reuse across related candidates and steps. Feasible-candidate compaction and identical-footprint reuse are now implemented. More reuse must respect power changes, departures, modulation-dependent physics and stale caches. Differentiable execution retains static traversal.
    5. Validate a supported custom-kernel backend. The ordinary-JAX tiled reduction is implemented here; the Pallas POC is isolated in a separate worktree. Backend support, register use, differentiation and generic/corrected modes need their own validation before production adoption.
    6. Rework RSA's registry-based capacity accumulation if it becomes dominant. It still evaluates registry rows across all slots and performs path ownership reductions. The present 420-slot measurement does not justify claiming a gain.

    Exact XPM remains quadratic in the number of interacting channels for the current direct formulation. The original masking adds candidate and network-link factors; this change removes much redundant link/path work but does not eliminate channel pair interactions. The limited scaling from one to 16 environments shows that arithmetic and device data movement become important after allocation pressure is reduced.

    My assessment is that there is no demonstrated need for a C rewrite. JAX's JIT compilation already removes Python interpretation from these compiled loops. Algorithmic reuse, channel representation, fusion and compiler behavior are the immediate opportunities. Custom native code would need to improve those same kernels and data flows; changing the implementation language alone would not remove quadratic physical interactions or improve the model's validity.

    Reproduction and artifacts

    The benchmark is experimental/benchmarks/gn_scaling.py. On a GPU host:

    uv self update
uv sync --locked --group gpu
CUDA_VISIBLE_DEVICES=2 XLA_PYTHON_CLIENT_PREALLOCATE=false \
  uv run --locked python -m experimental.benchmarks.gn_scaling \
  --slots 420 --k 5 --iterations 15 --kernels link lightpath mask rollout \
  --output /tmp/gn-420.json --snapshot /tmp/gn-420.npz

CUDA_VISIBLE_DEVICES=2 XLA_PYTHON_CLIENT_PREALLOCATE=false \
  uv run --locked python -m experimental.benchmarks.gn_scaling \
  --slots 1376 --k 5 --warmup-steps 128 --iterations 10 \
  --kernels link lightpath mask rollout --output /tmp/gn-wide.json

uv run python -m experimental.benchmarks.gn_accuracy_audit --output /tmp/gn-audit.json

    Other options include --mode corrected, --mode nonuniform, --envs 16, and --env-type rsa_gn_model --kernels link lightpath throughput rollout. --occupancy 0.9 raises the synthetic target; the achieved occupancy is reported and can be substantially lower because placement attempts are bounded. Use --reference /tmp/original.npz for numerical/outcome assertions. Baseline and optimized runs should use the same script, precision setting and runtime when isolating code changes. To reproduce the original source, export commit 2256456, copy the benchmark script into it, and execute from that directory using the chosen environment's absolute Python path.

    Raw result JSON files are in docs/benchmarks/gn_20261024, including the original 420-slot result and the same-runtime optimized result. baseline-* uses the original source; optimized-* uses the restructured source; batch8-*, batch32-*, batch40-* and serial-candidates-* record batching experiments. Some batching experiments precede the final adaptive default; their implementation labels explain this. The partial baseline-latest-420.json is marked as timed out. Numerical comparison details are in validation.json.
